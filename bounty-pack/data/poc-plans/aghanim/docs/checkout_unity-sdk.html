Unity SDK reference

The Aghanim Unity SDK that allows you to use the Checkout within both your Android and iOS apps.

iOS. WebView

Android. Default browser

Android. In-app browser

Android. Native UI

Android. WebView

iOS. Safari browser

iOS. In-app Safari

iOS. WebView

Android. Default browser

Integration

To integrate the SDK, see its prerequisites and the detailed instruction on Integrate → Unity.

Upgrading from 1.13.2? See Migrate to Unity SDK 2.0.0.

Method reference

The SDK provides direct access to the Aghanim API through the Aghanim entity, in the AghanimSdk.Runtime.Api namespace.

Every method is asynchronous and reports its outcome through onSuccess and onError, invoked on the Unity main thread. Every method also takes an optional CancellationToken as its last parameter. See Error handling and Cancellation.

Editor and Standalone

The API works in the Editor, in Standalone players and in WebGL; for development, not for production use. Only LaunchMode.DefaultBrowser is supported there.

Initialize

To initialize the SDK, use the Initialize method. Call it once per game process, on the Unity main thread, before any other SDK method.

  • Callbacks
  • UniTask
  • C#
var config = new AghanimConfig("YOUR_SDK_API_KEY")
{
    // Optional. Default is AghanimLogLevel.NONE
    MinLogLevel = AghanimLogLevel.DEBUG
};

Aghanim.Initialize(
    config,
    onSuccess: () =>
    {
        // The SDK is ready. Make your first call from here
    },
    onError: (error) =>
    {
        // Log debug information for troubleshooting
        Debug.LogError($"Failed to initialize: {error.DebugMessage}");
    }
);
  • C#
private async UniTask InitializeAsync()
{
    var config = new AghanimConfig("YOUR_SDK_API_KEY")
    {
        // Optional. Default is AghanimLogLevel.NONE
        MinLogLevel = AghanimLogLevel.DEBUG
    };

    var result = await Aghanim.InitializeAsync(config);
    if (result.GetErrorOrNull() is { } error)
    {
        // Log debug information for troubleshooting
        Debug.LogError($"Failed to initialize: {error.DebugMessage}");
        return;
    }

    // The SDK is ready. Make your first call from here
}
ParameterTypeRequiredDescription
configAghanimConfigYesSDK configuration. Set the SDK API key, and optionally MinLogLevel and Logger.
onSuccessActionNoCallback that is invoked once the SDK is ready to use.
onErrorAction<ApiError>NoCallback that is invoked on failed result.

A second Initialize leaves the first configuration in effect, reports ApiError.AlreadyInitialized and never invokes onSuccess.

Get Order

To get Order details, use the GetOrder method.

  • Callbacks
  • UniTask
  • C#
Aghanim.GetOrder(
    orderId: "order_123",
    onSuccess: (order) =>
    {
        Debug.Log($"Order ID: {order.Id}");
        Debug.Log($"Player ID: {order.PlayerId}");
        Debug.Log($"Total price: {order.PriceMinorUnit} {order.Currency}");
    },
    onError: (error) =>
    {
        Debug.LogError($"Failed to get order: {error.DebugMessage}");
    }
);
  • C#
private async UniTask ShowOrderAsync(string orderId)
{
    switch (await Aghanim.GetOrderAsync(orderId))
    {
        case ApiResult<OrderRead>.Success success:
            var order = success.Value;
            Debug.Log($"Order ID: {order.Id}");
            Debug.Log($"Player ID: {order.PlayerId}");
            Debug.Log($"Total price: {order.PriceMinorUnit} {order.Currency}");
            break;
        case ApiResult<OrderRead>.Failure failure:
            Debug.LogError($"Failed to get order: {failure.Error.DebugMessage}");
            break;
    }
}
ParameterTypeRequiredDescription
orderIdstringYesUnique ID for the Order.
onSuccessAction<OrderRead>Yes if no errorCallback that is invoked on successful result.
onErrorAction<ApiError>Yes if no successCallback that is invoked on failed result.
cancellationTokenCancellationTokenNoCancels the call. See Cancellation.

Get unconsumed Orders

To know what Orders have been paid for but not granted yet, use the GetUnconsumedOrders method.

  • Callbacks
  • UniTask
  • C#
Aghanim.GetUnconsumedOrders(
    onSuccess: (response) =>
    {
        // Player has paid but not granted items from orders
        var unconsumedOrderIds = response.Orders;
        // TODO: Save order IDs for further consuming and granting
    },
    onError: (error) =>
    {
        // Log debug information for troubleshooting
        Debug.LogError($"Failed to get unconsumed orders: {error.DebugMessage}");
        // TODO: Handle error
    }
);
  • C#
private async UniTask CheckUnconsumedOrdersAsync()
{
    switch (await Aghanim.GetUnconsumedOrdersAsync())
    {
        case ApiResult<UnconsumedOrdersResponse>.Success success:
            // Player has paid but not granted items from orders
            var unconsumedOrderIds = success.Value.Orders;
            // TODO: Save order IDs for further consuming and granting
            break;
        case ApiResult<UnconsumedOrdersResponse>.Failure failure:
            // Log debug information for troubleshooting
            Debug.LogError($"Failed to get unconsumed orders: {failure.Error.DebugMessage}");
            // TODO: Handle error
            break;
    }
}
ParameterTypeRequiredDescription
onSuccessAction<UnconsumedOrdersResponse>Yes if no errorCallback that is invoked on successful result. Use response.Orders to access the array of order IDs.
onErrorAction<ApiError>Yes if no successCallback that is invoked on failed result.
cancellationTokenCancellationTokenNoCancels the call. See Cancellation.

When to use

GetUnconsumedOrders and ConsumeOrder are designed for games without a dedicated server (serverless). They allow you to handle item granting entirely on the client side.

If your game has a server, use the item.add webhook instead. It lets your server control item granting directly. See Handle post-payment events on game server-side in the integration guide.

When to call GetUnconsumedOrders depends on the launch mode you use:

Default browser, In-app browser, WebView, Custom per platform with Native UI (Android)

For these modes, subscribe to the standard Unity callbacks OnApplicationFocus and OnApplicationPause, which fire when the player returns to the app after completing the payment:

  • Callbacks
  • UniTask
  • C#
private void OnApplicationFocus(bool hasFocus)
{
    if (hasFocus)
    {
        CheckUnconsumedOrders();
    }
}

private void OnApplicationPause(bool isPaused)
{
    if (!isPaused)
    {
        CheckUnconsumedOrders();
    }
}

private void CheckUnconsumedOrders()
{
    Aghanim.GetUnconsumedOrders(
        onSuccess: (response) =>
        {
            foreach (var orderId in response.Orders)
            {
                ConsumeAndGrantOrder(orderId);
            }
        },
        onError: (error) =>
        {
            Debug.LogError($"Failed to get unconsumed orders: {error.DebugMessage}");
        }
    );
}
  • C#
private void OnApplicationFocus(bool hasFocus)
{
    if (hasFocus)
    {
        CheckUnconsumedOrdersAsync().Forget();
    }
}

private void OnApplicationPause(bool isPaused)
{
    if (!isPaused)
    {
        CheckUnconsumedOrdersAsync().Forget();
    }
}

private async UniTask CheckUnconsumedOrdersAsync()
{
    switch (await Aghanim.GetUnconsumedOrdersAsync(destroyCancellationToken))
    {
        case ApiResult<UnconsumedOrdersResponse>.Success success:
            foreach (var orderId in success.Value.Orders)
            {
                await ConsumeAndGrantOrderAsync(orderId);
            }
            break;
        case ApiResult<UnconsumedOrdersResponse>.Failure failure:
            Debug.LogError($"Failed to get unconsumed orders: {failure.Error.DebugMessage}");
            break;
    }
}

In-app browser and WebView (iOS)

On iOS, in addition to OnApplicationFocus / OnApplicationPause, the onViewClosed callback fires at the exact moment the player closes the view:

  • C#
var launchMode = new LaunchMode(
    android: AndroidLaunchMode.InAppBrowser(),
    ios: IOSLaunchMode.InAppBrowser(
        onViewClosed: (e) =>
        {
            // Earliest point to check order status on iOS
            CheckUnconsumedOrders();
        }
    )
);

Consume paid Order

To mark a paid Order as handled, use the ConsumeOrder method. Consuming the same Order twice fails, so grant its items once the consume succeeds.

  • Callbacks
  • UniTask
  • C#
Aghanim.ConsumeOrder(
    orderId: orderId,
    onSuccess: () =>
    {
        // Paid order is marked as consumed
        Debug.Log($"Order consumed: {orderId}");
        // TODO: Grant items in order to player
    },
    onError: (error) =>
    {
        // Log debug information for troubleshooting
        Debug.LogError($"Failed to consume order: {error.DebugMessage}");
        // TODO: Handle error
    }
);
  • C#
private async UniTask ConsumeOrderAsync(string orderId)
{
    var result = await Aghanim.ConsumeOrderAsync(orderId);
    if (result.GetErrorOrNull() is { } error)
    {
        // Log debug information for troubleshooting
        Debug.LogError($"Failed to consume order: {error.DebugMessage}");
        // TODO: Handle error
        return;
    }

    // Paid order is marked as consumed
    Debug.Log($"Order consumed: {orderId}");
    // TODO: Grant items in order to player
}
ParameterTypeRequiredDescription
orderIdstringYesUnique ID for the Order.
onSuccessActionYes if no errorCallback that is invoked on successful result.
onErrorAction<ApiError>Yes if no successCallback that is invoked on failed result.
cancellationTokenCancellationTokenNoCancels the call. See Cancellation.

When to use

Call ConsumeOrder after fetching unconsumed orders. A consumed Order is not returned by GetUnconsumedOrders again.

  • UniTask
  • C#
private void ConsumeAndGrantOrder(string orderId)
{
    Aghanim.ConsumeOrder(
        orderId: orderId,
        onSuccess: () =>
        {
            Debug.Log($"Order consumed: {orderId}");
            // TODO: Grant items to player
        },
        onError: (error) =>
        {
            Debug.LogError($"Failed to consume order: {error.DebugMessage}");
        }
    );
}
  • C#
private async UniTask ConsumeAndGrantOrderAsync(string orderId)
{
    var result = await Aghanim.ConsumeOrderAsync(orderId);
    if (result.GetErrorOrNull() is { } error)
    {
        Debug.LogError($"Failed to consume order: {error.DebugMessage}");
        return;
    }

    Debug.Log($"Order consumed: {orderId}");
    // TODO: Grant items to player
}

Get items

To retrieve items with localized prices, use the GetItems method. The method returns items created in SKU Management → Items with prices localized based on the player's region.

The SKU list has no length limit. The SDK splits a large request into parallel batches, returns the items in the order you asked for them, and drops duplicate SKUs.

  • Callbacks
  • UniTask
  • C#
Aghanim.GetItems(
    skus: new List<string> { "your-item-sku" },
    onSuccess: (items) =>
    {
        foreach (var item in items)
        {
            // Use item.Name, item.Price.Display, item.ImageUrl to populate your store
            Debug.Log($"{item.Name}: {item.Price.Display}");
        }
    },
    onError: (error) =>
    {
        // Log debug information for troubleshooting
        Debug.LogError($"Failed to get items: {error.DebugMessage}");
        // TODO: Handle error
    }
);
  • C#
private async UniTask LoadStoreAsync()
{
    var skus = new List<string> { "your-item-sku" };

    switch (await Aghanim.GetItemsAsync(skus))
    {
        case ApiResult<Item[]>.Success success:
            foreach (var item in success.Value)
            {
                // Use item.Name, item.Price.Display, item.ImageUrl to populate your store
                Debug.Log($"{item.Name}: {item.Price.Display}");
            }
            break;
        case ApiResult<Item[]>.Failure failure:
            // Log debug information for troubleshooting
            Debug.LogError($"Failed to get items: {failure.Error.DebugMessage}");
            // TODO: Handle error
            break;
    }
}
ParameterTypeRequiredDescription
skusList<string>YesList of item SKUs to retrieve.
localeLocale?NoLocale for localization. Find the full list of supported locales in Checkout → Locales.
onSuccessAction<Item[]>Yes if no errorCallback that is invoked on successful result.
onErrorAction<ApiError>Yes if no successCallback that is invoked on failed result.
cancellationTokenCancellationTokenNoCancels the call. See Cancellation.

Create Checkout item

To create an item representation, use the CheckoutItem method. The item must already exist in SKU Management → Items, either created there or through the S2S API. Checkout rejects a SKU that is not in the game's catalog, and takes every price from the catalog; the client cannot set or override a price.

  • C#
var items = new List<CheckoutItem>
{
    new CheckoutItem("CRS-82500")
};
ParameterTypeRequiredDescription
skustringYesItem SKU from Dashboard.
namestringNoItem name from Dashboard.
descriptionstringNoItem description from Dashboard.
imageUrlstringNoItem image URL from Dashboard.

Create redirect behavior

To choose the behavior of redirecting the player after they have completed the payment successfully, use the RedirectSettings method.

  • Immediate
  • Delayed
  • No redirect

When the player has completed the payment, the SDK redirects them immediately to the deep link from backToGameUrl.

  • C#
var redirectSettings = new RedirectSettings(
    mode: RedirectMode.Immediate
);

When the player has completed the payment, the SDK shows the screen for the successful payment and then redirects the player to the deep link from backToGameUrl.

  • C#
var redirectSettings = new RedirectSettings(
    mode: RedirectMode.Delayed,
    delaySeconds: 5
);

When the player has completed the payment, they stay on the screen for the successful payment. To exit it, they manually close it or navigate away. After, you should redirect them to the deep link from backToGameUrl by yourself.

  • C#
var redirectSettings = new RedirectSettings(
    mode: RedirectMode.NoRedirect
);
ParameterTypeRequiredDescription
modeRedirectModeYesRedirect mode. Possible values: Immediate, Delayed, NoRedirect.
delaySecondsintYes if DelayedDelay in seconds. For Delayed mode, default is 5.

Use Checkout launch mode

To launch the payment form, use the LaunchMode entity.

  • In-app browser
  • Default browser
  • WebView
  • Custom per platform

For Android and iOS, the In-app browser launch mode creates the seamless players’ experience via Android Custom Tabs and iOS SFSafariViewController.

  • C#
LaunchMode.InternalBrowser

For Android and iOS, the Default browser launch mode works in the player default browser. Use the mode when you want to redirect the player outside your app.

  • C#
LaunchMode.DefaultBrowser

For Android and iOS, the WebView launch mode presents the Checkout inside a view the SDK owns, so the player never leaves your app. There is no LaunchMode.WebView shortcut; compose the mode per platform.

  • C#
var launchMode = new LaunchMode(
    android: AndroidLaunchMode.WebView(),
    ios: IOSLaunchMode.WebView(
        onViewClosed: (e) =>
        {
            // The player closed the WebView
            // You can check order status and grant items if needed
        }
    )
);

You can use different launch modes for each platform.

  • C#
var launchMode = new LaunchMode(
    android: AndroidLaunchMode.NativeUI(),
    ios: IOSLaunchMode.InAppBrowser()
);
ParameterTypeRequiredDescription
androidAndroidLaunchModeYesLaunch mode for Android platform. Possible values: NativeUI(), InAppBrowser(), DefaultBrowser(), WebView().
iosIOSLaunchModeYesLaunch mode for iOS platform. Possible values: InAppBrowser(), DefaultBrowser(), WebView().

On iOS, IOSLaunchMode.InAppBrowser() and IOSLaunchMode.WebView() accept an optional onViewClosed callback. It is invoked when the player closes the view. You can use it to check the order status and grant items when the player returns to the game.

  • C#
var launchMode = new LaunchMode(
    android: AndroidLaunchMode.InAppBrowser(),
    ios: IOSLaunchMode.InAppBrowser(
        onViewClosed: (e) =>
        {
            // The player closed the in-app browser
            // You can check order status and grant items if needed
        }
    )
);
ParameterTypeRequiredDescription
onViewClosedAction<CheckoutViewClosedEvent>NoCallback invoked when the view is closed on iOS.

Error handling

Every onError callback receives an ApiError, a closed hierarchy in the AghanimSdk.Runtime.Api.Result namespace. Branch on the case rather than parsing a message.

  • C#
private void OnError(ApiError error)
{
    switch (error)
    {
        case ApiError.Cancelled:
            // The call was cancelled; nothing to report to the player
            return;
        case ApiError.Network:
        case ApiError.Timeout:
        case ApiError.ServerUnavailable:
            ShowRetryPrompt();
            break;
        case ApiError.NotAuthenticated:
        case ApiError.NotAuthorized:
            ReAuthenticate();
            break;
        case ApiError.Server server:
            Debug.LogError($"HTTP {server.Code}: {server.DebugMessage}");
            break;
        case ApiError.InvalidArgument invalidArgument:
            Debug.LogError($"{invalidArgument.ArgumentName} is {invalidArgument.Reason}");
            break;
        default:
            Debug.LogError(error.DebugMessage);
            break;
    }
}

Later versions can add cases, so keep a default branch; without one a new failure goes unreported.

warning

DebugMessage is a non-localized diagnostic string, present on every case. Never show it to players.

Cancellation

Every method takes an optional CancellationToken as its last parameter. Tie it to the lifetime of the object making the call, so a scene teardown does not leave a callback pointing at a destroyed object.

  • Callbacks
  • UniTask
  • C#
public class StorePanel : MonoBehaviour
{
    private void OnEnable()
    {
        Aghanim.GetItems(
            skus: new List<string> { "your-item-sku" },
            onSuccess: (items) => Render(items),
            onError: OnError,
            // Unity cancels this token when the object is destroyed
            cancellationToken: destroyCancellationToken
        );
    }
}
  • C#
public class StorePanel : MonoBehaviour
{
    private void OnEnable()
    {
        LoadStoreAsync().Forget();
    }

    private async UniTask LoadStoreAsync()
    {
        // Unity cancels this token when the object is destroyed
        var result = await Aghanim.GetItemsAsync(
            skus: new List<string> { "your-item-sku" },
            cancellationToken: destroyCancellationToken
        );

        if (result is ApiResult<Item[]>.Success success)
        {
            Render(success.Value);
        }
    }
}

A token that is already cancelled skips the call. Otherwise onError receives ApiError.Cancelled once the cancellation is confirmed, or the real outcome if the operation finished first.

Async API

Every method on this page has a UniTask counterpart, shown in the UniTask tab of each example: InitializeAsync, SetPlayerIdAsync, ClearPlayerIdAsync, StartCheckoutAsync, PresentCheckoutAsync, GetOrderAsync, GetPricePointsAsync, GetItemsAsync, GetUnconsumedOrdersAsync and ConsumeOrderAsync.

Opt-in

The async API is compiled only when UniTask 2.5.10 or newer is installed. UniTask is not a dependency of the SDK package, so install it yourself; without it, these methods do not exist and the callback API is unaffected.

Each method returns UniTask<ApiResult<T>>, where ApiResult<T> is either Success carrying a Value or Failure carrying an Error. Operations that return nothing use ApiResult<Unit>.

Match on the case to use the value, or call GetErrorOrNull(), which returns the ApiError of a failure and null for a success, to keep an early return short.

The async methods take the CancellationToken as their last parameter, in place of the callbacks. StartCheckoutAsync and PresentCheckoutAsync take the launch mode as an optional parameter, defaulting to LaunchMode.Default.

They are safe to call from any thread and always complete on the Unity main thread. They never throw for an API failure; the failure arrives as ApiResult<T>.Failure.

FAQ

What platforms does your Unity SDK support?

The Unity SDK ships for both iOS and Android.

The API also works in the Editor, in Standalone players and in WebGL, where only LaunchMode.DefaultBrowser is supported; for development, not for production use.
